# Bounded native live-auth acceptance

Opt-in fixtures, usable from the Forge build or as an installed-package consumer.
Nothing here registers an automatic CTest login, installs software, adds system
trust, or manages existing accounts. The coordinator owns builds, containers,
Keycloak and the final acceptance record. The optional `keycloak/` fixture
provides a disposable HTTPS issuer; successful login is never inferred from
configuration or a healthy container.

## Prerequisites

- A coordinator-built Forge build-tree/package with the **real** enabled leaf:
  `Forge::forge_auth_appauth` on macOS, `Forge::forge_auth_oidc_agent` on Linux.
  Use CMake 3.31+, Ninja, C++23 and the same module-capable Clang/toolchain,
  build configuration, Boost and ABI as that Forge package. Do not point at the
  package-test fake `liboidc-agent.pc` or inject/preload replacement C symbols.
  CMake rejects known stub paths, not every possible substitution; dependency
  provenance remains the coordinator's responsibility.
- macOS 12+ in a logged-in GUI session with the default browser available,
  usable/unlocked Keychain and Forge's existing AppAuth **3.0.0** backend.
  `macos_driver.mm` runs `NSApplication` on the main thread. A joined fixture
  thread runs Asio; the provider dispatches its SDK work to the main queue.
  `appauth_driver.cpp` consumes the actual named Forge modules, avoiding an
  unsupported ObjC++/C++ module-BMI mix. No AppAuth calls are duplicated here.
- Linux with the real **5.3.8-systasis.1** `oidc-agent`, `oidc-gen`, `oidc-add`, public C
  library/headers and its required dependencies. GNU `timeout` bounds the
  external interactive setup below; `uuidgen` supplies disposable IDs. Use an isolated disposable agent, not a
  user's existing socket. A browser on another device may complete Device Flow.
- A coordinator-selected **HTTPS** issuer with discovery and certificates
  already trusted by the relevant OS/browser/agent. AppAuth rejects HTTP
  issuers: a plain-HTTP local Keycloak fixture is **not** this macOS gate.
  Never disable TLS verification. A local fixture may use an explicitly
  user-approved, temporary, localhost-only leaf certificate trust. The
  coordinator must remove that exact certificate and its trust after testing;
  the drivers never install trust themselves.
- Registered disposable **public** native clients, no client secret: macOS
  Authorization Code + PKCE S256 and AppAuth's ephemeral loopback redirect;
  Linux Device Authorization Grant and refresh enabled. The coordinator must
  allow the loopback URI actually generated by AppAuth (including its dynamic
  port), configure suitable consent/scopes, and ensure discovery advertises the
  Linux device endpoint. No password grant, injected refresh token or mock flow.
- A short access-token lifetime, preferably 30-60 seconds, with a valid refresh
  grant. The refresh fixture waits at most 300 seconds for actual expiry; a
  normal long-lived tenant token is unsuitable without a coordinator-approved
  test-client lifetime. Do not change a shared tenant's policy for this test.

Provider contracts: [AppAuth](../../../libraries/auth/appauth/README.md),
[oidc-agent](../../../libraries/auth/oidc_agent/README.md),
[OAuth2](../../../libraries/auth/oauth2/README.md).

## Build (coordinator only)

Run from the Forge repository root. Set `FORGE_PACKAGE_DIR` to the already-built
package directory containing `ForgeConfig.cmake`, and choose a separate
`LIVE_BUILD` directory. These commands do not build/configure Forge itself:

Alternatively, configure the existing Forge build with
`-DFORGE_BUILD_AUTH_LIVE_TESTS=ON` and build `forge_auth_live_appauth` or
`forge_auth_live_oidc_agent` with `-j 4`. This uses the same real leaf target and
dependencies without requiring an unrelated full package installation. The
option defaults to `OFF`; building a driver never starts a login.

```sh
export FORGE_PACKAGE_DIR=/coordinator/provided/forge-package
export LIVE_BUILD=/coordinator/provided/auth-live-build
```

macOS:

```sh
cmake -S tests/auth/live -B "$LIVE_BUILD" -G Ninja \
  -DForge_DIR="$FORGE_PACKAGE_DIR" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER=/opt/homebrew/opt/llvm/bin/clang++ \
  -DCMAKE_OBJCXX_COMPILER=/opt/homebrew/opt/llvm/bin/clang++ \
  -DCMAKE_OSX_SYSROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=12.0
cmake --build "$LIVE_BUILD" --target forge_auth_live_appauth -j 4
```

Linux (`FORGE_CXX` is the compiler used for the provided Forge package):

```sh
cmake -S tests/auth/live -B "$LIVE_BUILD" -G Ninja \
  -DForge_DIR="$FORGE_PACKAGE_DIR" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$FORGE_CXX"
cmake --build "$LIVE_BUILD" --target forge_auth_live_oidc_agent -j 4
```

No fallback/stub backend is supplied. A missing real leaf/package is a build
prerequisite failure, not a reason to replace the provider.

## Configuration And Flow Choices

CLI is strictly `--key value` (no `--key=value`). An optional `--config FILE`
reads a regular, non-symlink file of up to 8192 bytes of ASCII LF-delimited `key=value` lines, blank lines and
whole-line `#` comments. No quoting, spaces in values, interpolation or env
loading; CLI overrides file values. Unknown/duplicate keys in either source,
control characters and invalid bounds fail without echoing input. All values
are public configuration, never tokens, passwords or client secrets.

Keys: `issuer`, `client`, `account`, `run-id`, `flow`, `scopes` (comma-separated,
up to 8 unique scopes; an explicit empty value requests the provider's default
account profile), optional `audience`, `minimum-validity` (0-60 seconds,
default 10), `timeout` (5-900 seconds, default 180). The example file is
[live.conf.example](live.conf.example); replace its issuer/client placeholders
before use. Account must be exactly `live-<run-id>`. Run ID is a fresh lowercase
UUID, reused only across phases of one disposable acceptance run.

| Flow | macOS | Linux |
| --- | --- | --- |
| `authorize` | Require absent local state, then call `async_authorize`; browser interaction required; acquire afterwards. Existing usable state is not silently overwritten. | Unsupported by the Forge client. Run real `oidc-gen --flow=device` externally first. |
| `acquire` | Call `async_access_token`; SDK may use cached access or refresh state. No browser fallback. | Call the real provider's `async_access_token` by account name. |
| `resume` | Same provider acquisition in a **new executable process**, same service/account/config; no authorize call. | Same provider acquisition in a new process; agent retains its account. |
| `refresh` | Acquire, wait past returned expiry, acquire again through the SDK and require later expiry. | Same sequence through the real agent, which owns refresh. |
| `invalidate` | `async_invalidate`, then require typed `setup_required` from acquisition. Local removal only. | Unsupported: unload externally with `oidc-add --remove`. |

There is no Forge `resume` or force-refresh method; these are fixture flow
names. `async_revoke` is intentionally not used: AppAuth 3.0.0 does not expose
issuer-side revocation and the Forge provider reports it unsupported.

macOS service is fixed to `org.forge.tests.auth.live.<run-id>`, account to
`live-<run-id>`; arbitrary service/account overrides are impossible. These are
disposable **item names in the provider's default Keychain**, not a new physical
`.keychain-db`. The current provider API cannot select such a file. The driver
does not edit Keychain search lists/defaults/trust or query secret archives.
Only the provider accesses its isolated item, including its normal stale-state
cleanup. Never reuse the UUID for an unrelated account. Invalidate this one
item at the end; it does not revoke server sessions or clear browser SSO.

## macOS Login, Process Restart And Refresh

Select the issuer/client only after the tenant decision. Keep these public
values for the entire sequence:

```sh
export ISSUER=https://coordinator-selected-issuer/realms/forge-live
export CLIENT=coordinator-selected-public-native-client
export RUN_ID="$(uuidgen | tr '[:upper:]' '[:lower:]')"
export ACCOUNT="live-$RUN_ID"
export DRIVER="$LIVE_BUILD/forge_auth_live_appauth"
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow authorize --timeout 180
```

`READY/browser_user_action_required` is **not PASS** or proof the browser opened.
If a human click/login/consent is needed, report ready and hand control to the
user. Do not automate credentials or claim completion. The process may remain
waiting within its deadline while the user completes AppAuth's browser flow.
Continue only after exit 0 and its final `PASS/authorize`:

```sh
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow resume
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow refresh --timeout 360
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow resume
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow invalidate
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow acquire
```

Each invocation exits before the next: this is real process restart, not
reconstructing a provider in one process. The second resume checks persisted
post-refresh state. Final acquire must exit 3 with `BLOCKED/setup_required`.
Run invalidate also after a failed/canceled run using that same isolated ID.

## Linux Real Agent Device Flow

Use a disposable shell/container. Select the Linux Device Flow client; preserve
these public values and the new isolated agent environment for this sequence:

```sh
umask 077
export ISSUER=https://coordinator-selected-issuer/realms/forge-live
export CLIENT=coordinator-selected-public-device-client
export RUN_ID="$(uuidgen | tr '[:upper:]' '[:lower:]')"
export ACCOUNT="live-$RUN_ID"
export OIDC_CONFIG_DIR="$(mktemp -d)"
unset OIDC_SOCK OIDCD_PID
eval "$(oidc-agent --no-autoload --no-autoreauthenticate)"
timeout --foreground --kill-after=5s 300s oidc-gen --manual --pub \
  --flow=device --issuer "$ISSUER" --client-id "$CLIENT" \
  --scope 'openid profile offline_access' --no-url-call "$ACCOUNT"
```

This is the real agent's Device Flow, not driver-implemented OAuth. In a private
interactive terminal, the user visits the agent-provided verification URL and
enters its user code, then completes any encryption-password prompt. Do not
capture that terminal's codes/config/password in acceptance artifacts. If a
click is required, stop coordination and report ready; do not continue to a
token probe until account generation succeeds. `oidc-gen` normally adds the
generated account; if explicitly necessary, load it with `oidc-add "$ACCOUNT"`.

After successful Device Flow, with the same `OIDC_SOCK` and isolated config dir:

```sh
export DRIVER="$LIVE_BUILD/forge_auth_live_oidc_agent"
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow acquire
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow resume
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow refresh --timeout 360
oidc-add --remove "$ACCOUNT"
"$DRIVER" --issuer "$ISSUER" --client "$CLIENT" --account "$ACCOUNT" \
  --run-id "$RUN_ID" --flow acquire
```

The final probe must exit 3 (`--no-autoload` prevents a hidden reload).
Unloading is neither file deletion nor issuer-side revocation. Stop only this
disposable agent with `oidc-agent --kill` in this same isolated shell; do not
run it against a pre-existing `OIDCD_PID`. Retain encrypted account files only
as allowed by the coordinator's disposable-environment retention policy.

Never use `oidc-token`, `oidc-gen --only-at/--print`, `oidc-add --print`, debug,
HTTP tracing, shell `set -x`, secrets in CLI/env or a mocked socket for this gate.
The driver uses one bounded Forge compute worker with no pending queue and one
waiting submission. The agent's blocking C call has no hard cancellation.
Normal completion stops admission and awaits pool shutdown before PASS.

Official agent references: [Device Flow and CLI options](https://indigo-dc.github.io/oidc-agent/usage/oidc-gen/options/),
[agent isolation options](https://indigo-dc.github.io/oidc-agent/usage/oidc-agent/options/),
[account unloading](https://indigo-dc.github.io/oidc-agent/usage/oidc-add/options/).
Forge requires the pinned version above; the coordinator must verify that
version's binaries and real library, not infer compatibility from latest docs.

## Evidence And Bounds

Stdout is JSONL with fixture-owned status/event labels, success boolean, public
expiry epoch-seconds (`0` when not applicable) and `issuer_match_count` (0/1).
No tokens, token lengths/digests, JWT decoding, subjects, account/client/issuer
strings, request/response bodies, SDK errors or exception `what()`/context.
Issuer comparison uses provider metadata; it is **not** verified user identity,
JWT signature/audience/scope validation or resource-server authorization.
Linux `client` is public setup documentation input: the provider selects an
agent account and cannot verify its client ID through this API.
`metadata_observed` records only returned expiry and issuer equality before
assertions. It is not a success result and must not be interpreted as token
validation. Explicit overrides and the default account profile are distinct
acceptance cases; passing one does not waive a failure in the other.

Only final `PASS/<flow>` plus exit 0 completes that phase. Earlier `EVENT`
records are observations, not PASS. Exit 1 is provider/assertion failure, 2 is
invalid config/unsupported flow (including expiry wait over 300s), 3 is
setup/user-action/cancellation blockage, 124 is deadline. On deadline the
fixture emits BLOCKED, requests cancellation and allows a 5-second grace.
It then `_Exit(124)` if needed to bound an uncancelable external call; that
disposable-process escape skips destructors and is not a production lifecycle
pattern. External agent/browser activity can remain; the coordinator owns its
isolated cleanup. Default total bound is 185 seconds, maximum 905 seconds.

`refresh` uses real wall clock and checks public provider-result metadata,
issuer equality, future expiry and expiry advancement after actual expiration.
Minimum validity is checked with a 1-second allowance for provider expiry
truncation. There is no time travel, direct refresh endpoint call or token
comparison. These observations prove post-expiry acquisition without the driver
calling authorize; they do not alone prove which issuer grant was used.
Coordinator acceptance must also establish real dependency provenance, the
successful human Device Flow, separate-process ordering, and issuer-side
refresh-grant evidence from **safe event counts only**, never raw token traffic.
Do not label a whole platform gate PASS merely because one probe passed.
